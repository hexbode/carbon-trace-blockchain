# 接口清单

- 基地址：`http://localhost:8080`
- 请求/响应体：`application/json`（文件上传为 `multipart/form-data`）
- 鉴权：除标注「免登录」外，均需携带请求头 `Authorization: Bearer <token>`

**免登录白名单**（见 `WebMvcConfig`）：`/api/auth/login`、`/api/public/**`、`/api/certifications/by-fingerprint/**`、`/api/certifications/verify`

**通用返回码**

| 码 | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数缺失或非法（含请求体格式错误、上传超限） |
| 401 | 未登录 / token 无效 |
| 403 | 已登录但角色无权限 |
| 404 | 资源不存在（含查询未命中） |

**角色取值**：`enterprise`（企业端）、`regulator`（监管端）、`auditor`（审核端）、`admin`（系统管理员，拥有全部权限）

## 16. 合规判定 `/api/compliance`

合规规则（配额、环比波动、活动数据缺失、排放因子不符、迟报）由链上智能合约 `CarbonCompliance` 判定；
后端只负责聚合入参、解读结果与治理参数管理。

`flags` 位掩码：`1` 配额超限 / `2` 环比超阈值 / `4` 活动数据为 0 / `8` 因子不符 / `16` 迟报；
`flags = -1` 表示链不可用且未产生判定（`onChain=false`，此时 `compliant` 返回 `null`）。

| 方法 | 路径 | 权限 | 参数 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/api/compliance/check` | 登录 | body：`enterpriseId`、`period`、`sourceCode`、`activityData`、`factor` | 试算判定（不落库）；缺企业编号或报告期返回 400 |
| GET | `/api/compliance/certificate/{certId}` | 登录 | 路径参数 | 证书的链上合规判定快照 |
| GET | `/api/compliance/quota` | 登录 | `enterpriseId`、`year` | 查链上年度配额 |
| PUT | `/api/compliance/quota` | regulator / admin | body：`enterpriseId`、`year`、`quota` | 设置年度配额（合约写）；配额为负返回 400 |
| GET | `/api/compliance/threshold` | 登录 | — | 查可治理参数：`thresholdBp`、`thresholdPercent`、`lateReportMonths` |
| PUT | `/api/compliance/threshold` | regulator / admin | body：`thresholdBp`、`lateReportMonths`（至少一项） | 修改可治理参数（合约写）；阈值超出 0~10000 基点返回 400 |

> `POST /api/compliance/check` 返回示例：
> ```json
> {
>   "flags": 2, "onChain": true, "compliant": false, "notice": null,
>   "deltaBp": 2530, "deltaPercent": "25.3%", "previousFactor": 2.5,
>   "quota": 1000.00, "yearToDate": 1250.00, "thresholdBp": 2000, "thresholdPercent": "20.00%",
>   "items": [{ "rule": "fluctuation", "type": "data_anomaly", "typeLabel": "数据异常", "level": "high" }]
> }
> ```
>
> 公共端见第 2 节 `GET /api/public/compliance/{fingerprint}`（免登录，返回 `flags` / `compliant` / `items`）。

### Outbox 与 RabbitMQ

- 申报包 `generate / submit / review` 在**同一数据库事务**内写入 `cbam_outbox`，避免业务成功但消息丢失；
- 中继 `CbamOutboxRelay` 每 5 秒轮询 NEW/到期的 FAILED 事件，通过 `cbam.events`（topic）投递；
- 主队列 `cbam.regulator.sync` 消费失败进入死信 `cbam.dlx` → `cbam.regulator.sync.dlq`；
- 投递失败按 30s → 60s → 120s → 240s → 300s 退避重试；
- 消费端按 `messageId = outbox.event_id` 幂等，`cbam_regulator_inbox.event_id` 唯一索引兜底；
- 配置：`carbon.cbam.outbox.mq-enabled`（默认 false，演示环境 true）、`relay-interval-ms`、交换机/队列名均可覆盖。

### 数据版本与定时对账

- `cbam_data_versions` 按「企业 + 年度」维护 `version`：排放记录新增/修改/删除时原子 +1；
- 申报包生成时把当时的版本写入 `cbam_declarations.data_version`（快照版本）；
- 读取申报包时实时返回 `liveVersion` 与 `dataChanged`（版本或合计任一不一致即视为已变化）；
- `CbamReconciliationJob` 默认每小时整点执行 `reconcile()`，把快照版本/实时版本、快照合计/实时合计与结论写入 `cbam_reconciliation_logs`；
- 监管端「立即对账」调用同一逻辑，「对账记录」查看日志。

### 完整性规则

申报包生成时逐项校验并写入 `missingItems`：年度无排放数据、产量为 0、隐含排放为 0、
以及 **actual 数据缺少同年度同装置 verified 核查报告**。存在任何缺失项时 `completeness=incomplete`，
不可提交；补齐后重新生成即可。
